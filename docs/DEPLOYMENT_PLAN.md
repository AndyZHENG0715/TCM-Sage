## What the repository actually serves

- `web/package.json` pins Next.js 16.1.6 / React 19.2.3. `web/app/api/backend/[...path]/route.ts:3` resolves `BACKEND_URL`, then `NEXT_PUBLIC_BACKEND_URL`, then localhost. Its GET/POST proxy streams request and response bodies. `web/lib/api.ts:11` sends browser traffic to `/api/backend`; source and KG explorer pages also depend on those endpoints. Thus the frontend currently needs a Node HTTP runtime, not only a file host.
- `src/api.py` is the FastAPI HTTP entrypoint, binding `0.0.0.0:$PORT` (8000 default). It exposes query SSE, configuration, source-context/full-book, graph search/subgraph, Arena query/vote/models/stats and health. Chroma is embedded storage, and NetworkX is an in-process graph, not separate HTTP servers.
- A query runs classification, retrieval, generation and verification: `src/ui_backend.py:743–830`. Text SSE precedes final `event: metadata`; metadata includes citations, severity, verification and citation bounds. `web/lib/types.ts` distinguishes text citations (number, source, content, chunk ID, scores) and graph citations (fact, depth, provenance). A successful health response only proves the HTTP process responds; it does not exercise retrieval, model access or citation validity.
- Real retrieval uses `text-embedding-v4`, 1024 dimensions, international DashScope endpoint, and optional `qwen3-rerank` (`src/embeddings.py`). Formula and clause searches can embed more than once; normal retrieval initially asks for at least 20 candidates (`src/ui_backend.py:451–613`). Generation provider does not change the embedding provider.
- `src/main.py:147–304` supports OpenAI, Google, Anthropic, OpenRouter, Together, Alibaba and local Ollama/LM Studio. `LLM_MODEL`, classifier and verifier settings can differ; the API currently accepts caller-supplied provider/model/retrieval overrides. No server-enforced model price allowlist, access-code check, rate limit, token limit or budget ledger was found. CORS defaults to `*`; CORS is not authentication. `load_dotenv()` is used in several modules, with `override=True` in embeddings; production must use host secret settings and ship no `.env` files. No secret files were opened for this audit.
- Existing uncommitted `DEMO_MODE=1` bypasses Chroma/embedding/rerank through local bigram scoring; `DEMO_LLM=1` separately replaces `create_llm()` models with a local template. Both still need Python and corpus loading. Neither is a prerecorded static website. The module's broad offline docstring/banner overstates what `DEMO_MODE` alone guarantees; preserve the file and correct its wording with a future approved behavior/documentation change.
- More critically, `src/arena.py:92–124` bypasses that factory: the plain side directly constructs a DashScope client and invokes DDGS web search, even though it reads `LLM_PROVIDER`. Consequently even both flags together do not guarantee an entirely offline Arena. Historical Gemini Arena success in HANDOFF is not evidence that both branches used Google. Disable the public live Arena by default.
- `/arena/vote` accepts arbitrary response text and caller-provided mapping and appends JSONL (`src/arena.py`, `src/api.py`). It is not a validated research collection endpoint. Do not expose write access or historical raw comments/session records in the public showcase.
- The verifier initializes its result to `SUPPORTED` and leaves it there if the verification call fails (`src/ui_backend.py:796–805`). Citation bounds only establish that marker numbers exist, not that assertions are true. Future live output must distinguish unavailable verification. `web/hooks/useKeepAlive.ts` also polls health every ten minutes; remove that background dependency from static replay rather than relying on it to keep a free service warm.

## Data and recovery audit

Read-only JSON inspection with the Windows project venv found 12,204 chunks; 388 records with Shanghan Lun clause metadata, 489 with Jingui clause metadata; 18,450 graph entities and 21,476 relationships. `chunks.json` is 14,563,978 bytes; SymMap JSON is 12,982,095 bytes; the 17 source text files total 10,753,533 bytes. These are disk sizes, not RAM estimates. Source texts, processed chunks, graph and crosswalks are tracked; `git ls-files vectorstore` is empty and `vectorstore/chroma` is absent. No actual vectorstore size can be quoted. The float32 embedding payload alone would be 12,204 × 1,024 × 4 = 49,987,584 bytes, excluding indexes, metadata, SQLite and runtime memory; this is a lower-component estimate, not disk sizing evidence.

`ingest_checkpoint.json` contains 12,592 IDs despite the absent store. `src/ingest.py:358–438` rewrites chunks, creates directories and skips checkpoint IDs. Running it blindly could both alter read-only evidence and skip missing vectors. Do not run ingestion during this phase or automatically during deployment. A future vector recovery needs a separately approved budget, consistent snapshot/checkpoint manifest, hashes, collection count and sample-query verification. Preserve the original corpus and old checkpoint; do not reset them silently. A disk purchase does not restore the missing index.

The dependency list also includes Torch, transformers, sentence-transformers, Streamlit and platform-specific packages. No Linux clean build, memory fit or reduced deployment requirements have been verified. Do not promise that the current Windows venv or full requirements installs unchanged on a 512 MB Linux service. Any dependency changes need the applicable approval.

Pre-generate curated `/source/[chunkId]` and `/kg/[entityId]` routes, or explicitly adapt their navigation to a static query-based viewer. Keep the local presentation server path available. Static replay must never fall back to a live endpoint on fixture failure. Package source paragraph/chapter text and highlight offsets with each chosen citation, plus recorded graph nodes/edges/cited IDs. Preserve provenance from approved crosswalk mappings; graph expansion beyond the recorded neighborhood is visibly unavailable, not fetched live. Freeze verification labels as historical output, not a current clinical check.

Monthly cost at zero requests: **US$0 / HK$0**. At 500 replay sessions: **US$0 / HK$0**, within the cited static offering and limits. This is 500 prerecorded interactions, not arbitrary live questions. No backend sleep or model quota failure; asset download, browser work and chosen replay pacing determine latency. No measured millisecond promise. If an answer or graph file fails, show a labelled unavailable state and retry/download link, without starting inference. ## Option B — static showcase plus optional free live preview

Frontend: the same independent Cloudflare static showcase. Backend: one Render Free FastAPI instance; no Next.js Node proxy service. Vectorstore: absent; use the existing local corpus retrieval with `DEMO_MODE=1` and real generation only behind the proposed controls. This is a lower-cost preview of the local retriever, not evidence that Chroma retrieval has been restored. Graph/source reads come from tracked evidence; curated replay remains independent of backend health.

The later live client needs an explicit HTTPS backend URL with backend-validated access code and narrowly allowed frontend origins. This is a proposed change to `CONTRIBUTING.md`'s proxy-only convention and the frontend API adapter; update both together after approval, rather than silently circumventing the convention. A backend URL is public configuration; credentials are not.

[Render Free](https://render.com/docs/free) allows 750 instance-hours/workspace/month, sleeps after 15 minutes without inbound traffic and takes about a minute to wake; filesystem changes are lost on restart/redeploy/spin-down, and disks are unavailable. [Compute plans](https://render.com/docs/compute-plans) give Free 0.1 CPU / 512 MB. This app's fit is unmeasured; an OOM or dependency-build failure means fallback to replay, not an automatic paid upgrade. A free instance is unsuitable for promises of production uptime. No keep-alive pings to defeat sleep.

There is no verified durable free budget ledger in this architecture. Therefore live access stays disabled after every restart until the operator supplies a conservative remaining allowance; reserve the full allowance as spent on process start, use one process, and never automatically re-grant it after restart. Lost state must deny live access. If that operational constraint is unacceptable, B is replay-only until a separately approved persistent ledger exists. No Arena votes are retained. Render documents behavior without a payment method, but no guarantee every account avoids anti-abuse card verification; if a card is demanded, stop and retain A.

At zero live queries: **US$0 / HK$0** hosting and inference. At 500 controlled live queries: **US$6.75 / HK$52.65** under the Gemini scenario below, or **US$2.205 / HK$17.20** under the Qwen scenario. These are conditional API charges, not guaranteed free live allowances or permission to activate billing. Provider free-tier limits, regional eligibility, RAM and build fit remain gates. First-token delay includes Render wake-up plus corpus/index loading, classification, retrieval and generation; no measured warm/cold latency exists. After a 90-second total live deadline or provider error, offer prerecorded replay labelled as such, never substitute it as a generated answer to the arbitrary query.

## Reproducible inference budget

Use **US$1 = HK$7.8** as a declared planning conversion, not a live FX quote. The [HKMA linked-rate explanation](https://www.hkma.gov.hk/eng/key-functions/money/linked-exchange-rate-system/) describes a 7.75–7.85 band; card spreads/tax are additional. All prices checked 2026-10-23; recheck before phase 2b's provider decision.

Model scenario G: `gemini-3.5-flash-lite`, Standard text rates **US$0.30 / million input tokens** and **US$2.50 / million output tokens including thinking**, from [Google pricing](https://ai.google.dev/gemini-api/docs/pricing). This is a proposed budget model, not the handoff's `gemini-3.8-flash` configuration or evidence of SDK compatibility. [Google's region list](https://ai.google.dev/gemini-api/docs/available-regions) lists Taiwan/Singapore but does not list Hong Kong. Residence/account eligibility must be established by Andy; hosting in Singapore does not establish eligibility. [Lifecycle documentation](https://ai.google.dev/gemini-api/docs/deprecations) restricts Gemini 2.5 to previous active users, so its older low rate is not the new-project baseline. Free-tier data handling and quotas differ; no free quota is credited here and no sensitive patient data belongs in this prototype.

Model scenario Q: Singapore/International `qwen3.8-flash`, non-thinking, **US$0.15 / million input** and **US$0.47 / million output**, from [Alibaba's pricing](https://www.alibabacloud.com/help/en/model-studio/model-pricing). Same three-stage token assumptions; model access, non-thinking controls, SDK/endpoint compatibility and account billing still require confirmation. Neither scenario inherits eligibility from the existing secret file.

For one permitted non-Arena query, propose exactly three LLM requests, no hidden automatic retries/tools/web grounding: classifier <=2,000 input / 128 output tokens; answer <=8,000 input / 2,000 output; verifier <=10,000 input / 872 output. This totals **20,000 input + 3,000 billable output tokens** including reasoning, prompts, context and history. Reject oversized input before invoking a provider; do not assume a character count equals a token count. Provider output/thinking settings must enforce these maxima, and failed or disconnected requests retain their reserved cost until reconciled.

- G: `(20,000 × 0.30 + 3,000 × 2.50) / 1,000,000 = US$0.0135/query`; 500 = **US$6.75**.
- Q: `(20,000 × 0.15 + 3,000 × 0.47) / 1,000,000 = US$0.00441/query`; 500 = **US$2.205**.
- For real vector mode add a maximum aggregate 2,000 embedding input tokens per query, including repeated clause/formula calls, plus 20,000 total billed reranker input tokens across candidates. Singapore `text-embedding-v4` US$0.07/million and `qwen3-rerank` US$0.10/million add **US$0.00214/query / US$1.07 per 500**. Local `DEMO_MODE=1` retrieval has none of these provider charges. Regional keys/endpoints must match; trial grants are excluded. Corpus embedding rebuild is a separate, currently unpriced one-time cost because billable token counts have not been measured.

These are proposed enforceable envelopes; today's application does not enforce them. No claim is made that its default output/context will fit. If tokenization, reasoning accounting or SDK output controls cannot be verified for the chosen model, live access remains off.

## Proposed controls before any public live access

1. **Default replay, fail closed:** a server-side `LIVE_ENABLED=false` concept, separate from retrieval/stub flags; public replay never invokes backend health/config/source/graph/model endpoints. Future emergency switch disables all paid paths on the backend, not merely a UI button. Remove the provider key to revoke access if necessary; static replay stays available.
2. **Backend access code:** store only salted code hashes and provider keys in the host secret store; use HTTPS and constant-time checking, no shared code in source, URL or bundled JavaScript. Validate on every query before provider initialization; direct requests with missing/invalid code return 401/403 and make zero provider calls. Fix the API's arbitrary provider/model overrides with an allowlist and fixed caps on the server. A public URL and CORS do not protect spending.
3. **Concrete initial limits, subject to Andy's choice:** 2 live queries/minute and 10/day per IP; 2/minute and 20/day per code; one concurrent query per code and two globally; 500 live queries/month globally. Determine client IP only from trusted host proxy headers; bound question/body/history, graph hops/results and source responses. Rate-limit denied attempts and public read routes too. Disable `/arena/query` and `/arena/vote` on the backend by default, including direct calls; expose only a redacted, frozen final-report preference summary.
4. **Atomic spend reservations:** propose **US$0.50/day and US$10/month globally** as upper ceilings for API use, reset at 00:00 UTC, plus Andy's separately chosen provider monthly ceiling. Reserve maximum stage costs before admission, including all embedding/rerank work; stop when count, concurrency, daily, monthly or provider allowance is exhausted. Use the lowest remaining allowance, and deny if the ledger/rates/usage are unavailable. Reservation survives restart in C; B follows the prepaid process-allowance rule above. Decrement global remaining budget atomically, never by a periodically checked dashboard balance. No retry can bypass the reservation.
5. At those enforced proposed settings, API spending is bounded by the smaller of US$10/month and the 500-query price envelope: G local **US$6.75**, G vector **US$7.82**; Q local **US$2.205**, Q vector **US$3.275**. They are conditional ceilings for this endpoint only, not other users of the same provider account or hosting overages. SDK retries must be disabled or separately reserved. Provider alerts/budget dashboards alone are not a hard stop. Where no provider hard stop exists, say so and require the app ledger plus a low prepaid allowance; do not promise a provider-enforced limit.
6. Display “Research prototype — not medical advice. Answers and citations can be wrong; verify the original source.” in English and Chinese above the composer and on replay/live output. No patient identifiers or clinical-service positioning; no accuracy, clinical validation or no-hallucination claims. Log minimal operational usage, not questions, full responses, access codes or keys; redact exception strings before returning API errors.
